# Domain docs

## Before exploring

Read `GLOSSARY.md` at the repository root and the ADRs under `docs/adr/` relevant to the work. Proceed with the files that exist.

Keep one glossary and one ADR directory for the workspace. Use `domain-modeling` to create the glossary when the first term is settled and the ADR directory when the first decision is recorded.

## Use the domain vocabulary

Use glossary terms in issue titles, refactor proposals, hypotheses, and test names. If a term is missing, check how the project uses it and bring any gap to `domain-modeling`.

## Flag ADR conflicts

If a proposal contradicts an ADR, cite it and explain why the decision should be reopened.
